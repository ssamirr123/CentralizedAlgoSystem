# Instrument Resolver Fix

## Root cause

`trading.validation.angel_readonly._pick_current_nifty_ce_symbol()` sorted candidate expiries by calendar date and always selected `expiries[0]` — the nearest date — with **no check for whether that date's own trading session had already ended**. Angel's public NFO scrip master does not remove an expired weekly contract's row until it refreshes (typically the next trading day), so once the market closed on a weekly expiry day, the function kept returning that now-unusable, already-settled contract as "the nearest expiry" indefinitely, until the scrip master itself changed.

## Old behavior

```
sorted(expiries, key=date) -> take expiries[0] unconditionally
```

No distinction between "nearest future date," "today, market still open," and "today, market already closed" (or any date in the past that the scrip master hadn't dropped yet).

## Corrected behavior

Every candidate expiry is now filtered through a new `_is_expiry_still_tradable(expiry_date, now)` check before selection:

```
expiry_date < today                          -> REJECTED (in the past)
expiry_date == today, before session close   -> ACCEPTED (still tradable today)
expiry_date == today, at/after session close -> REJECTED (today's session has ended)
expiry_date > today                          -> ACCEPTED (a genuine future expiry)
```

`now` is resolved via the project's own existing `trading.market_data.market_hours.now_in_tz(market_tz())` (Asia/Kolkata) — no duplicate calendar/timezone implementation was introduced, per this phase's own instruction. The session-close constant (`15:30 IST`) mirrors the same value `trading/common/risk_manager.py` already uses for its own `MARKET_SESSION_VALIDATION` check.

Additionally:
- A malformed expiry string (unparseable date) is now skipped rather than crashing the whole resolution.
- An expiry with no matching CE rows (a symbol/expiry mismatch) is now skipped in favor of the next valid candidate, rather than returning an empty/garbage result.
- If **no** valid, tradable expiry exists at all, the function now raises `ValueError` explicitly — fails closed, never silently falls back to an expired contract.

ATM strike-selection logic (rounding to the nearest 50, closest-strike selection) was **not** changed — only expiry eligibility was touched, kept isolated from strike/CE-PE selection exactly as this phase requires.

## Expiry-selection rules (final)

See "Corrected behavior" above — this is the complete rule set; no additional cutoff or heuristic was introduced beyond what those four cases require.
